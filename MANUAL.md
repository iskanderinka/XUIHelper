# Руководство по эксплуатации Telegram-бота для 3x-ui (V2)

## 1. Обзор

Этот бот помогает управлять **несколькими** панелями 3x-ui и следить за ними прямо из Telegram. Поддерживается многопользовательский и многопанельный режим, есть развитые функции администратора и автоматические задачи.

- **Администратор**: полный контроль — настройка бота, управление всеми панелями и пользователями, получение автоматических уведомлений.
- **Обычный пользователь**: может запрашивать информацию только о своих нодах на разрешённых панелях (по привязанному email).

## 2. Требования к окружению

- **Python**: 3.8 или выше
- **Зависимости**: все пакеты из `requirements.txt`, установленные через `pip`

## 3. Подготовка

### 3.1. Получение токена Telegram-бота

1.  Найдите в Telegram `BotFather` и начните диалог.
2.  Отправьте команду `/newbot` и следуйте подсказкам.
3.  После создания BotFather выдаст **токен**. Скопируйте его и сохраните в надёжном месте.

### 3.2. Получение вашего Telegram User ID

1.  Найдите в Telegram `userinfobot` и начните диалог.
2.  Бот сразу пришлёт ваши данные, включая `Id` — это и есть ваш User ID.

## 4. Первичная настройка (администратор)

### 4.1. Файл конфигурации

Создайте в корне проекта файл `config.yml` и заполните его по образцу:

```yaml
# 1. Токен Telegram-бота от BotFather
bot_token: "YOUR_TELEGRAM_BOT_TOKEN"

# 2. Список авторизованных пользователей
users:
  # Первый admin_user считается супер-администратором
  admin_users:
    - 123456789  # Замените на ваш Telegram User ID
  # Список обычных пользователей (опционально)
  normal_users:
    - 987654321

# 3. Список панелей 3x-ui (основная часть конфигурации)
# Здесь можно заранее прописать все панели
panels:
  # "Произвольное имя панели": { ... }
  # Пример:
  # "Мой сингапурский узел":
  #   url: "http://your-panel-url.com:port"
  #   username: "your_username"
  #   password: "your_password"
  # "Резервный сервер":
  #   url: "http://another-panel.com:port"
  #   username: "admin"
  #   password: "password123"

```

**Важно**: старое поле `panel_config` устарело. Используйте поле `panels` для управления панелями.

### 4.2. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 4.3. Запуск бота

Запуск в переднем плане (для отладки):
```bash
python main.py
```

Для долгой и стабильной работы используйте `nohup`, `tmux` или `screen`, чтобы бот работал в фоне:
```bash
nohup python main.py &
```

## 5. Использование функций

### 5.1. Команды администратора

| Команда | Параметры | Описание |
| :--- | :--- | :--- |
| `/setting` | нет | Диалоговое добавление или обновление панели. |
| `/listpanels`| нет | Список всех панелей, прописанных в `config.yml`. |
| `/delpanel` | `<имя панели>` | Удалить панель из конфигурации. |
| `/status` | `[имя панели]` | Статус панели. С именем — подробный статус сервера; без имени — краткая сводка по всем панелям. |
| `/adduser` | `<ID>` | Добавить обычного пользователя с правом на запросы. |
| `/deluser` | `<ID>` | Убрать обычного пользователя. |
| `/listusers` | нет | Список администраторов и обычных пользователей. |
| `/help` | нет | Справка. |

### 5.2. Команды обычного пользователя

| Команда | Параметры | Описание |
| :--- | :--- | :--- |
| `/query` | `<панель> <имя>` | Запрос информации о ноде по имени (email) на указанной панели: расход трафика и срок действия. |
| `/help` | нет | Справка. |


## 6. Автоматические задачи (администратор)

Бот содержит встроенные автоматические задачи, они работают без ручного запуска:

- **Оповещение о недоступности панели**: периодически (по умолчанию каждые 6 часов) проверяется доступность всех панелей. Если панель недоступна, все администраторы получают уведомление.
- **Напоминание об истечении нод**: бот автоматически сканирует инбаунды всех панелей. Если инбаунд истекает в течение **3 дней**, все администраторы получают уведомление.

## 7. FAQ

**В: Почему `/query myuser` не работает?**
О: Бот поддерживает несколько панелей, поэтому при запросе нужно указывать панель. Формат: `/query <панель> <имя>`. Пример: `/query Мой сингапурский узел myuser`.

**В: Бот сообщает «Слишком частые запросы. Временная блокировка». Почему?**
О: Для защиты от злоупотреблений предусмотрена блокировка: если за короткое время (5 минут) пользователь **5 раз** запросил несуществующего пользователя, доступ временно блокируется (по умолчанию на 2 часа). Проверьте имя панели и email и подождите.

**В: Как сделать, чтобы бот работал в фоне и не останавливался после закрытия SSH?**
О: Используйте `nohup python main.py &` или `tmux`/`screen`.

## 8. Развёртывание через Docker (рекомендуется)

Docker упрощает развёртывание и обеспечивает одинаковое окружение.

### 8.1. Подготовка

1.  Убедитесь, что на сервере установлены [Docker](https://docs.docker.com/engine/install/) и [Docker Compose](https://docs.docker.com/compose/install/).
2.  Клонируйте или скачайте исходники проекта на сервер.

### 8.2. Конфигурация

Как и при ручном развёртывании, сначала создайте и заполните `config.yml`. См. раздел **[4.1 Файл конфигурации](#41-файл-конфигурации)**.

### 8.3. Запуск бота

В корне проекта выполните:

```bash
docker-compose up -d --build
```

### 8.4. Управление ботом

-   **Просмотр логов**:
    ```bash
    docker-compose logs -f
    ```

-   **Остановка и удаление контейнера**:
    ```bash
    docker-compose down
    ```

-   **Пересборка после обновления кода**:
    1.  Остановить контейнер: `docker-compose down`
    2.  Забрать свежий код: `git pull`
    3.  Пересобрать и запустить: `docker-compose up -d --build`
