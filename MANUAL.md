# Руководство по эксплуатации Telegram-бота для 3x-ui

## 1. Обзор

Бот управляет несколькими панелями 3x-ui прямо из Telegram: создаёт клиентов,
выдаёт им ссылки подписки, следит за сроком действия, поддерживает паузу и
продление. Параллельно ведёт статистику трафика и присылает ежедневные отчёты.

- **Клиент**: получает подписку и кнопки быстрого доступа от бота.
- **Администратор**: создаёт клиентов, управляет подписками, смотрит статистику.
- **Суперадмин**: первый ID в списке `admin_users`. Управляет панелями
  (добавление, удаление). Эти команды недоступны обычным админам.

## 2. Файлы проекта

| Файл | Назначение |
|------|-----------|
| `main.py` | Логика бота: команды, диалоги, задачи по расписанию |
| `config.py` | Работа с `config.yml`, валидация URL панелей |
| `database.py` | SQLite: трафик, привязки клиентов, пользователи бота, уведомления |
| `xui_api.py` | HTTP-клиент панели 3x-ui 3.8.x |
| `query_logic.py` | Поиск клиента по email для `/mystatus`-подобных проверок |
| `config.yml` | Личный конфиг (токен, панели, админы) — **не коммитится** |
| `config.yml.example` | Шаблон конфига для новых установок |
| `MIGRATION.md` | Инструкция по переносу бота и настройке SSL |
| `data/traffic.db` | Локальная база данных |
| `tests/` | Автотесты |

## 3. Требования

- Python 3.9+ (рекомендуется 3.11)
- Зависимости из `requirements.txt`

## 4. Подготовка

### 4.1. Получение токена бота

1. Telegram → `@BotFather` → `/newbot`.
2. Скопируй токен.

### 4.2. Получение Telegram User ID

1. Telegram → `@userinfobot` → `/start`.
2. Скопируй `Id`.

## 5. Первичная настройка

### 5.1. `config.yml`

Скопируй `config.yml.example` в `config.yml` и заполни:

```yaml
bot_token: "YOUR_TELEGRAM_BOT_TOKEN"

users:
  # Список ID администраторов. ПЕРВЫЙ — суперадмин.
  # Без суперадмина админские команды не работают.
  admin_users:
    - 197066617       # ← суперадмин
    - 123456789       # обычный админ (опционально)

panels:
  "TMT":
    url: "https://185.200.190.40:24487/x8UGpUW143YI9P3JVyQm"
    username: "mvernita"
    password: "..."
    sub_url: "https://185.200.190.40:2096/sub"

policy:
  url: ""             # URL политики конфиденциальности
  message: ""         # если пусто — стандартный текст

tariffs:
  url: ""             # URL страницы с тарифами
  message: ""         # если пусто — стандартный текст
```

**Важно:**

- URL панели должен содержать префикс (`/x8UGpUW143YI9P3JVyQm`), если он настроен.
- URL панели — с `127.0.0.1`, если бот и панель на одном сервере.
- URL панели — внешний, если бот на другой машине (см. `MIGRATION.md`).

### 5.2. Установка и запуск

```bash
pip install -r requirements.txt
python3 main.py
```

Для фона — `nohup`, `tmux`, `screen` или Docker (см. раздел 10).

## 6. Команды

### 6.1. Для всех пользователей

| Команда | Описание |
|---------|----------|
| `/start` | Начать работу с ботом, зарегистрировать TG ID |
| `/help` | Справка (разная для админа и клиента) |
| `/policy` | Политика конфиденциальности (если URL задан) |
| `/mylink` | Получить свою sub-ссылку |

### 6.2. Кнопки быстрого доступа клиента

Появляются в чате автоматически после выдачи подписки:

| Кнопка | Действие |
|--------|----------|
| 🔗 Ссылка подписки | Присылает sub-ссылку клиента |
| 📊 Тарифы | Сообщение с inline-кнопкой на страницу тарифов |
| 🆘 Нужна помощь | Уведомляет всех админов о запросе клиента |

### 6.3. Для администраторов

| Команда | Описание |
|---------|----------|
| `/addclient <tg_id> <email> <панель> <id1> [id2]...` | Создать клиента |
| `/revoke <tg_id> [email]` | Удалить клиента из панели и БД |
| `/pausesub <tg_id> [email]` | Приостановить подписку |
| `/resumesub <tg_id> [email]` | Возобновить и продлить на дни паузы |
| `/extendsub <tg_id> <+N \| дата> [email]` | Продлить подписку |
| `/listclients` | Список клиентов (постранично, по 5) |
| `/getlink <tg_id> [email]` | Получить sub-ссылку клиента |
| `/inbounds <панель>` | Список инбаундов с ID |
| `/status <панель>` | Подробный статус панели |
| `/listpanels` | Список панелей со статусом Xray |
| `/report` | Дневной отчёт по трафику |

### 6.4. Только для суперадмина

| Команда | Описание |
|---------|----------|
| `/setting` | Диалог добавления или обновления панели |
| `/delpanel <имя>` | Удалить панель из конфига бота |

**Почему это критично:** `/setting` может подменить URL/логин/пароль панели,
а `/delpanel` — отвязать панель от бота (сама панель продолжит работать, но бот
потеряет к ней доступ).

## 7. Сценарии работы

### 7.1. Выдача подписки новому клиенту

1. **Клиент** нажимает `/start`. Бот запоминает TG ID.
2. **Клиент** сообщает админу свой TG ID.
3. **Админ** создаёт клиента:

   ```
   /addclient 123456789 user123 TMT 8 9
   ```

4. **Бот** спрашивает HWID лимит.
5. **Админ** вводит число (например, `3`) или `/skip`.
6. **Бот** спрашивает срок подписки и показывает кнопки:

   ```
   [7 дней] [14 дней]
   [1 месяц] [6 месяцев]
   [1 год]
   ```

   Можно нажать кнопку или ввести дату `ГГГГ-ММ-ДД`, либо `/skip` для бессрочной.

7. **Бот** спрашивает комментарий (виден только админам).
8. **Бот** показывает превью и запрашивает подтверждение:

   ```
   ⚠️ Подтверди действие
   **Создать клиента:**
   - TG ID: `123456789`
   - Email: `user123`
   - Панель: `TMT`
   - Инбаунды: `[8, 9]`
   - HWID лимит: `3`
   - Срок: до `2026-12-31`
   - 💬 Комментарий: Иван с работы

   [✅ Да] [❌ Нет]
   ```

9. **Бот** создаёт клиента в панели, сохраняет связку, отправляет клиенту
   sub-ссылку и reply-клавиатуру, а админу присылает отчёт с `Sub ID`
   (без полной ссылки).

### 7.2. Повторная выдача ссылки клиенту

- Клиент нажимает кнопку **🔗 Ссылка подписки** или пишет `/mylink`.
- Если подписка на паузе — бот ответит «подписка приостановлена».

### 7.3. Пауза и возобновление

Клиент уехал на 2 недели, попросил поставить на паузу:

```
/pausesub 123456789 user123 → [✅ Да]
```

Клиент вернулся:

```
/resumesub 123456789 user123 → [✅ Да]
```

Бот автоматически **продлит срок** на число дней паузы. Трафик не тратится, дни не теряются.

### 7.4. Продление подписки

```
/extendsub 123456789 +30              # +30 дней к текущему сроку
/extendsub 123456789 2026-12-31       # установить дату
/extendsub 123456789 +30 user123      # конкретная связка
```

### 7.5. Удаление клиента

```
/revoke 123456789 user123 → [✅ Да]
```

Удаляет клиента из панели **и** из БД бота. Ссылка перестанет работать.

## 8. Автоматические задачи

| Задача | Когда | Что делает |
|--------|-------|-----------|
| `check_inbounds_job` | Каждые 6 часов | Проверяет связь с панелями, алерт если недоступна |
| `record_traffic_job` | Ежедневно в 23:50 (Asia/Hong_Kong) | Снимок трафика всех клиентов |
| `daily_report_job` | Ежедневно в 8:00 (если включён) | Дневной отчёт админам |
| `expiry_notification_job` | Ежедневно в 9:00 | Напоминания клиентам (7 и 3 дня) и алерт админам после истечения |

**Отчёт заработает через сутки** после запуска бота — нужно два снимка трафика
подряд, чтобы посчитать разницу.

## 9. Суперадмин

**Суперадмин — первый ID в `users.admin_users`.**

Если его нет (или список пуст) — **все админские команды заблокированы**,
бот напишет: «Суперадмин не назначен. Зайди на сервер и добавь ID первым в
`users.admin_users` файла `config.yml`».

Чтобы назначить/сменить суперадмина — правь `config.yml` руками и перезапускай бота.

## 11. FAQ

**В: Клиент не получает подписку после `/addclient`.**
О: Проверь, что он нажал `/start`. Без этого Telegram не даёт ботам писать
первыми.

**В: Как узнать ID инбаунда?**
О: `/inbounds TMT` покажет список.

**В: Клиент просит вернуть ссылку.**
О: Админ может дать `/getlink 123456789 user123` — ссылка придёт в личку админу
(не в историю чата с клиентом).

**В: Что если автоматика по сбросу трафика не сработает?**
О: Автосброс отключён. Клиенты на безлимите — трафик не считается критичным.
Если нужно обнулить клиенту счётчик — сделай это руками в панели.

**В: Почему `/report` показывает «данные за день недоступны»?**
О: Отчёту нужны два снимка трафика (за вчера и позавчера). Первые сутки
после запуска — не работает.

**В: Забыл, на каком инбаунде сидит клиент.**
О: `/listclients` — увидишь список с инбаундами и комментариями.
