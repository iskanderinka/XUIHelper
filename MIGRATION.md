# Миграция панели и настройка SSL

Этот документ описывает, как безопасно подключить бота к панели 3x-ui
в разных схемах размещения: локально (на одном сервере) и удалённо
(бот и панель на разных машинах).

---

## Сценарий 1. Бот и панель на одном сервере (рекомендуемый)

Это самый безопасный вариант. Трафик между ботом и панелью не покидает
машину — MITM физически невозможен.

### Что делать

1. **Проверь, что панель слушает на `0.0.0.0` или `127.0.0.1`.**

   В 3x-ui: **Настройки панели → Panel Listen IP**.
   - Если там `0.0.0.0` — всё ок, ничего не меняй.
   - Если конкретный внешний IP — добавь `127.0.0.1` в список
     (или замени на `0.0.0.0`, если хочешь, чтобы панель была доступна
     снаружи для админа).

2. **В `config.yml` укажи URL панели через локальный адрес:**

   ```yaml
   panels:
     "TMT":
       url: "https://127.0.0.1:24487/x8UGpUW143YI9P3JVyQm"
       username: "mvernita"
       password: "..."
       sub_url: "https://185.200.190.40:2096/sub"
   ```

   **Важно: `sub_url` оставь внешним.** Клиенты ходят снаружи, им нужен
   внешний IP/домен. Локальный адрес нужен только боту.

3. **Убедись, что в `xui_api.py` включено автоопределение verify.**
   Если в `__init__` стоит безусловный `verify=False` — замени на
   `self._resolve_verify_setting()` (см. актуальный код).

4. **Проверь:**
   - `/status TMT` — работает.
   - `/inbounds TMT` — работает.
   - В логах нет предупреждений про CA bundle.

### Преимущества

- Полная защита от MITM без сертификатов.
- Ничего не надо обновлять каждые 90 дней.
- Работает без домена.

## Сценарий 2. Бот и панель на разных серверах (свой сертификат)

Если панель на сервере A, а бот на сервере B — трафик идёт через интернет.
Тогда `verify=False` опасен: MITM возможен.

### Вариант A. Let's Encrypt (если есть домен)

1. Купи/используй домен, направь A-запись на IP панели.
2. В 3x-ui: **SSL Certificate Management** → выбери **Let's Encrypt**,
   укажи домен. Панель сама получит сертификат.
3. В `config.yml` замени URL панели на домен:
   ```yaml
   url: "https://panel.example.com:24487/x8UGpUW143YI9P3JVyQm"
   ```
4. В `xui_api.py` автоопределение само поставит `verify=True`,
   потому что домен — не `127.0.0.1`, а `certs/panel_cert.pem` нет.
   Сертификат Let's Encrypt — доверенный, httpx его проверит.

### Вариант B. Свой самоподписанный сертификат (без домена)

Если домена нет, но панель и бот на разных машинах — придётся
скачать сертификат панели и подсунуть его боту.

**Шаг 1. Найди сертификат панели.**

Он лежит на сервере панели. Типичные пути:
- `/etc/ssl/self_signed_cert/` (если ставил через установочный скрипт),
- `/root/cert/` (если задавал пути вручную).

Точный путь виден в 3x-ui: **Настройки панели → Panel Certificate
Public Key Path**.

**Шаг 2. Скачай его на сервер, где работает бот.**

```bash
scp user@panel_ip:/etc/ssl/self_signed_cert/fullchain.pem \
    /path/to/bot/certs/panel_cert.pem
```

Создай папку `certs/` в корне проекта бота, если её нет:
```bash
mkdir -p /path/to/bot/certs
```

**Шаг 3. Проверь, что автоопределение в `xui_api.py` включено.**

Файл `certs/panel_cert.pem` уже лежит, и `_resolve_verify_setting`
вернёт путь к нему автоматически, если URL панели — внешний.

**Шаг 4. Проверь:**

```bash
python3 - <<'EOF'
import asyncio
from xui_api import XUIApi
async def main():
    api = XUIApi(
        url="https://panel_ip:24487/префикс",
        username="...",
        password="...",
    )
    async with api:
        ok = await api.login()
        print("login:", ok)
asyncio.run(main())
EOF
```

Должно быть `login: True`.

**Если сертификат панели обновится** (переустановка, смена) — надо
снова скачать `fullchain.pem` и заменить файл в `certs/`.

## Сценарий 3. Миграция: с одного сервера на разные

Если ты сначала держал бота и панель на одной машине, а потом
переносишь бота на другую — вот чек-лист:

1. На новой машине скопируй проект и `config.yml`.
2. Проверь, что на новой машине есть доступ к IP панели (ping, curl).
3. Открой `config.yml`, поменяй URL панели:
   - было `https://127.0.0.1:24487/префикс`
   - стало `https://внешний_ip_панели:24487/префикс`
4. Скачай сертификат панели на новую машину (см. Сценарий 2, вариант B).
5. Положи в `certs/panel_cert.pem`.
6. Запусти бота, проверь `/status`.
7. Убедись, что в логах нет предупреждений про CA bundle.

**Обратная миграция (с разных на один)** — просто поменяй URL на
`https://127.0.0.1:...` и удали `certs/panel_cert.pem` (он больше не нужен).

---

## Проверка защищённости

Если хочешь убедиться, что всё правильно:

1. Открой `config.yml`.
2. Если URL панели начинается с `https://127.0.0.1` или
   `https://localhost` — всё в порядке, MITM невозможен.
3. Если URL внешний — проверь, что файл `certs/panel_cert.pem`
   существует и не пустой.
4. Запусти бота. Если в логе есть предупреждение
   `нет CA bundle — verify=True без сертификата упадёт` — значит,
   ты в опасной конфигурации и надо её поправить.
