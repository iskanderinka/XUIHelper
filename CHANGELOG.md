# Changelog

Все значимые изменения проекта документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии следуют [Semantic Versioning](https://semver.org/lang/ru/).

## [1.2.0] - 2026-10-10

### Added

- **`/getlink` — выдача конфигураций.** Команда теперь показывает админу диалог с двумя вариантами: sub-ссылка или прямые ссылки на каждый инбаунд клиента. Второй вариант берёт ссылки из API панели (`/panel/api/clients/links/:email`) и присылает по одному сообщению на связку, с каждой ссылкой в `<code>`-блоке. Актуально при блокировке sub-порта провайдером.
- **Журнал действий администраторов.** Новый модуль `audit.py` пишет вызовы команд и результаты операций в `data/audit.log`. Ведётся человекочитаемо, по строке на событие, с визуальным разделителем при смене календарного дня. Автоматическая ротация при превышении файлом 1 МБ.
- **Команда `/broadcast`.** Рассылка сообщений всем пользователям бота или конкретному TG ID. С превью перед отправкой, прогрессом доставки (обновляется каждые 50 сообщений) и итоговым отчётом «доставлено / не доставлено». Задержка между отправками 50 мс — не более 20 msg/sec, чтобы не поймать flood-лимит Telegram.

### Changed

- **Разметка сообщений: Markdown → HTML во всём проекте.** Причина — Telegram падает с `can't parse entities`, когда в динамических данных (имена инбаундов, email) встречаются символы `_`, `*`, `` ` ``, `[`, `]`. Все сообщения с динамическими данными экранируются через `html.escape`. Команды, отправлявшие список инбаундов (`/inbounds`), перестают ругаться на имена с подчёркиваниями.
- **Документация приведена к актуальному состоянию.** Полностью переписаны `README.md`, `MANUAL.md` и `MIGRATION.md`. Добавлены разделы про журнал действий, Туркменистан-специфику, Let's Encrypt for IP, тестирование sub-порта из клиентской сети. Все примеры обезличены — IP, логины и пути заменены на плейсхолдеры. Файл `ver.md` переименован в `CHANGELOG.md` и приведён к формату Keep a Changelog.

### Fixed

- **Снимки трафика для `/report` собираются штатно.** Устранён пропуск задачи `record_traffic_job` в определённых условиях.
- **`_format_bytes`.** Размеры ровно на границе (1024 B, 1024 KB и т.д.) отображались как «1024.00 B» вместо «1.00 KB». Заменено `>` на `>=` в условии цикла нормализации.

## [1.1.0] - 2026-09-29

### Added

- **Команда `/broadcast`.** Рассылка сообщений всем пользователям бота или конкретному TG ID. С превью перед отправкой, прогрессом доставки и итоговым отчётом.

### Changed

- **Разметка сообщений: Markdown → HTML во всём проекте.** Причина — Telegram падает с `can't parse entities` при символах `_`, `*`, `` ` ``, `[`, `]` в динамических данных.

## [1.0.0] - 2026-09-25

### Added

- **Принудительная синхронизация раз в сутки.** Задача `auto_sync_job` обходит панели, сверяет БД с реальным состоянием и уведомляет админов об изменениях.
- **Синхронизация HWID.** `/sync` теперь подтягивает из панели актуальный `limit_hwid` клиентов.

### Changed

- **Продакшн-токен.** Бот переведён с тестового токена на основной.
- **Единый часовой пояс.** Все операции — задачи по расписанию, расчёт «конца дня», даты в БД — считаются в зоне из `config.yml`.

### Fixed

- **Ввод полной даты при продлении и создании подписки.** Устранены проблемы парсинга, из-за которых валидные даты формата `ГГГГ-ММ-ДД` отклонялись.

## [0.10.0] - 2026-09-22

### Added

- **Вторая строка админской reply-клавиатуры.** Добавлены кнопки «Переименовать» и «Комментарий».

### Changed

- **Клиентский интерфейс переведён на туркменский язык.** Reply-клавиатура, приветствие, ответы на кнопки — на туркменском.
- **Клиентские статьи билингвизированы.** Разделы про политику, тарифы и гайды доступны в двух языках.

## [0.9.9] - <YYYY-MM-DD> — Release Candidate

### Added

- **Развёртывание на сервере.** Бот запущен в продакшн-подобной среде.
- **SSH SOCKS5-туннель для Telegram.** Настроен обход блокировки через удалённый сервер.

### Notes

- Работа на тестовом токене.
- Открыт доступ внешнему администратору для обкатки.
- Итерация отладки и поиска багов.
- Согласование терминологии и нейминга в клиентском интерфейсе.
